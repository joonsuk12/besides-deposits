# 결정 기록

대화에서 정한 것을 날짜순으로 쌓는다. 새 결정은 아래에 추가하고, 뒤집힌 결정은 지우지 말고 "→ 변경"으로 표시한다.

## 2026-11-11 — 프로젝트 시작

### 배경
- 자산관리 대화를 여러 환경에서 이어가려고 private 레포 `asset-management`를 만들었다.
- 그 과정에서 예전 팀 프로젝트 NewStocks/NewStocks를 로컬에서 띄워 써 볼까 검토했다.

### NewStocks 분석 결과
- 구성: Spring Boot 3.1(Java 17, 8200) + Next.js 13.4 + Flask 서버 3개(pykrx 주가 수집, 국내 뉴스 크롤링·BERT 감성분석·DBSCAN 군집화, 해외 뉴스 Selenium 크롤링) + 챗봇 서버(LangChain·FAISS) + MySQL(AWS RDS).
- 그대로 띄우기 어려운 이유: `.env` 없음, 운영 DB 내려갔을 가능성, 프론트가 운영 주소 고정, 로그인이 카카오·구글 OAuth뿐, 라이브러리 노후, PC에 Java·MySQL·Docker 없음.
- 공개 레포 `server/DomesticNews/app/app.py`에 DB 계정·비밀번호가 평문으로 남아 있음 (정리 필요, 미완료).

### 결정
1. **NewStocks를 띄우지 않고 가볍게 새로 만든다.** 가져올 것은 "차트 위에 뉴스 표시" 기능과 pykrx 수집·뉴스 처리 아이디어.
2. **백엔드는 FastAPI.** 사용자는 Spring 개발자라 코드를 이해할 수 있을지 걱정했다 → Spring식 계층 구조로 짜고, 파일마다 대응 주석을 달고, 흐름을 설명하며 진행하기로 했다. Django는 숨은 관례가 많아 제외.
3. **코드 레포를 자산 기록 레포와 분리한다.** 이유: 금융정보 보호, Claude 맥락 분리, 커밋 기록 분리, 코드 부속 파일 분리.
4. **기능 범위**: 차트 + 뉴스(관심 종목) + 증권사 리포트 요약(가급적 전체) + 공시. 사용자가 주식 초보이므로 리포트는 "초보가 어디를 봐야 하는지" 기준으로 틀에 맞춰 요약한다.
5. **리포트 요약은 2단계**: 전체 리포트는 간단 요약, 관심 종목과 직접 고른 리포트는 상세 요약. 결과는 DB에 저장.
6. **레포 이름** `stock-newbie-stroll`(주식초보나들이), private.
7. **첫 관심 종목**: 삼성전자, SK하이닉스, 두산, 펨트론.
8. **화면은 처음부터 Next.js.** 처음엔 Jinja2 템플릿(Thymeleaf와 비슷)을 추천했으나, 화면이 앱 수준으로 커질 것이라는 사용자 의견에 따라 변경. 백엔드는 JSON API만 담당.
9. **추가 요금 없이 구현한다.** 무료 데이터 출처, 로컬 실행, 유료 LLM API 미사용. 요약은 사용자의 Claude 구독 안에서 Claude Code 예약 작업으로 처리하는 방식을 기본안으로 한다 (3단계에서 구체화).
10. **개발 환경**: Windows 11, Python 3.12, Node.js 22 (기존 3.9 / 16에서 추가 설치).

## 2026-11-11 — 1단계 구현

- 백엔드 `stock` 도메인: `GET /stocks`, `GET /stocks/{code}/prices?days=`, `POST /stocks/collect`. 관심 종목 4개의 3년치 일봉(각 729일)을 SQLite에 저장.
- 프론트: 종목 선택, 기간(3개월·1년·3년), 캔들 + 거래량 차트, 날짜를 누르면 그날 시가·고가·저가·종가·거래량 표시, 캔들 읽는 법 안내. 뉴스·리포트 자리는 비워 둠.
- **백엔드 포트를 8000 → 8100으로 변경.** 이 PC에서 8000번은 SMPortal(Django)이 쓰고 있어 충돌했다.
- 주가 출처는 pykrx 우선, 실패 시 FinanceDataReader. pykrx는 KRX 로그인 경고를 내지만 일봉 조회는 된다.
- 관심 종목 목록은 지금 `backend/app/stock/collector.py`의 `WATCHLIST`에 코드로 들어 있다. 화면에서 추가·삭제하는 기능은 아직 없다.
- 사용 버전: Next.js 16, React 19, lightweight-charts 5, FastAPI + SQLAlchemy 2.

## 2026-11-11 — 화면 구성 변경 (작업 중단 시점)

사용자 요청: 시작 페이지는 NewStocks 것을 그대로, "내 관심종목" 메뉴에서 리포트·사업보고서를 보고, 나머지는 NewStocks처럼 종목 검색 → 차트.

- 시작 페이지(`/`): NewStocks 랜딩(01·02·03 섹션, 푸터)을 옮기고 이름만 바꿈. 어두운 남색 + 민트 테마도 NewStocks를 따름.
- 헤더: 로고, 종목 검색(이름·코드·초성, NewStocks SearchBox), 차트 / 내 관심종목 메뉴. 커뮤니티·로그인은 제외.
- 차트 화면(`/{종목코드}`): 왼쪽 관심종목 목록, 가운데 차트(마우스 툴팁, ☆로 관심 추가/해제), 오른쪽 선택한 날 정보. 뉴스 자리는 비워 둠.
- 관심종목 화면(`/watchlist`): 종목별 종가, 증권사 리포트·공시 자리(3·4단계 예정). 그전까지 네이버 리서치·DART 원문 링크.
- 백엔드: 전체 종목 목록(코스피·코스닥·ETF 약 3,960개)을 서버 첫 실행 때 받아 둠. 검색한 종목은 차트를 열 때 주가를 받아 저장(하루 한 번). 관심 종목을 DB(`stock.is_watched`)로 관리, API `GET /stocks/watchlist`, `PUT·DELETE /stocks/{code}/watch` 추가.
- 차트 라이브러리: NewStocks도 TradingView Lightweight Charts를 썼다. 같은 라이브러리의 새 버전(5)이라 바꿀 이유가 없다. TradingView "고급 차트 위젯"은 데이터가 TradingView 쪽에 있어 우리 뉴스·리포트 표시를 얹을 수 없어 쓰지 않는다.
