## 2026-11-11 — 프로젝트 시작

### 배경
- 자산관리 대화를 여러 환경에서 이어가려고 private 레포 `asset-management`를 만들었다.
- 그 과정에서 예전 팀 프로젝트 NewStocks/NewStocks를 로컬에서 띄워 써 볼까 검토했다.

### NewStocks 분석 결과
- 구성: Spring Boot 3.1(Java 17, 8200) + Next.js 13.4 + Flask 서버 3개(pykrx 주가 수집, 국내 뉴스 크롤링·BERT 감성분석·DBSCAN 군집화, 해외 뉴스 Selenium 크롤링) + 챗봇 서버(LangChain·FAISS) + MySQL(AWS RDS).
- 그대로 띄우기 어려운 이유: `.env` 없음, 운영 DB 내려갔을 가능성, 프론트가 운영 주소 고정, 로그인이 카카오·구글 OAuth뿐, 라이브러리 노후, PC에 Java·MySQL·Docker 없음.
- 공개 레포 `server/DomesticNews/app/app.py`에 DB 계정·비밀번호가 평문으로 남아 있음 (정리 필요, 미완료).

### 결정
1. **NewStocks를 띄우지 않고 가볍게 새로 만든다.** 가져올 것은 "차트 위에 뉴스 표시" 기능과 pykrx 수집·뉴스 처리 아이디어.
2. **백엔드는 FastAPI.** 사용자는 Spring 개발자라 코드를 이해할 수 있을지 걱정했다 → Spring식 계층 구조로 짜고, 파일마다 대응 주석을 달고, 흐름을 설명하며 진행하기로 했다. Django는 숨은 관례가 많아 제외.
3. **코드 레포를 자산 기록 레포와 분리한다.** 이유: 금융정보 보호, Claude 맥락 분리, 커밋 기록 분리, 코드 부속 파일 분리.
4. **기능 범위**: 차트 + 뉴스(관심 종목) + 증권사 리포트 요약(가급적 전체) + 공시. 사용자가 주식 초보이므로 리포트는 "초보가 어디를 봐야 하는지" 기준으로 틀에 맞춰 요약한다.
5. **리포트 요약은 2단계**: 전체 리포트는 간단 요약, 관심 종목과 직접 고른 리포트는 상세 요약. 결과는 DB에 저장.
6. **레포 이름** `stock-newbie-stroll`(주식초보나들이), private.
7. **첫 관심 종목**: 삼성전자, SK하이닉스, 두산, 펨트론.
8. **화면은 처음부터 Next.js.** 처음엔 Jinja2 템플릿(Thymeleaf와 비슷)을 추천했으나, 화면이 앱 수준으로 커질 것이라는 사용자 의견에 따라 변경. 백엔드는 JSON API만 담당.
9. **추가 요금 없이 구현한다.** 무료 데이터 출처, 로컬 실행, 유료 LLM API 미사용. 요약은 사용자의 Claude 구독 안에서 Claude Code 예약 작업으로 처리하는 방식을 기본안으로 한다 (3단계에서 구체화).
10. **개발 환경**: Windows 11, Python 3.12, Node.js 22 (기존 3.9 / 16에서 추가 설치).

## 2026-11-12 — 리포트 분석 요약·뉴스 키포인트

사용자 요청: "네이버 리서치의 분석 요약, 뉴스의 키포인트 집어내는 걸 중점적으로".

### 데이터 출처 결정
- 네이버 금융이 개편되어 리서치 목록 HTML이 비어 있고, 데이터는 네이버 증권 **내부 API**로만 온다.
- 공식 API(네이버 검색 API, OpenDART)와 내부 API의 차이를 설명했고, 사용자가 **개인용·저빈도 조건으로 내부 API 사용을 허용**했다.
- Claude Code 자동 모드의 권한 검사가 내부 API 호출과 권한 설정 수정을 막아서, 사용자가 권한 모드를 "승인 요청" 방식으로 바꾼 뒤 진행했다.
- 사용 중인 주소: 리포트 `stock.naver.com/api/stockSecurity/researches/v2/company?index&size(≤50)&startDate&endDate`, 종목별 `.../company/by-items?itemCodes&size(≤10)`, 뉴스 `stock.naver.com/api/domestic/detail/news?itemCode&page&pageSize`. 확인용 스크립트: `backend/scripts/probe_naver_research.py`.
- 요청 간격 0.5초, 같은 데이터는 30분(오늘 리포트·뉴스)~3시간(종목별 리포트) 안에 다시 요청하지 않는다. 지난 날짜 리포트는 한 번만 받는다.

### 키포인트 규칙 (유료 AI 없이)
- 리포트: 증권사 요약문의 굵은 소제목 = 한 줄 결론 (영어 꼬리표면 제목 사용), 숫자·판단어 점수 상위 3문장 = 핵심 근거, 우려·부진 같은 말이 긍정어보다 많은 문장 = 조심할 점, 용어사전 46개 중 나온 것 = 용어 풀이, 같은 증권사 직전 리포트와 비교한 목표주가 상향/하향/유지, 최근 종가와 목표주가 차이(%).
- 뉴스: 네이버가 묶어 준 기사 수 = 중요도("기사 N건"), 미리보기 첫 문장 = 한 줄 요약, 긍정·부정 단어 수로 분위기 추정("추정"으로 표시), 실적·수주 등 주제 꼬리표.

### 화면
- 새 화면 `오늘의 리포트`(/reports): 날짜 이동, 필터(관심종목·목표가 상향·하향·의견 없음), 검색. 카드에서 "자세히"로 근거·리스크·용어를 펼침.

## 2026-11-14 — PER·PBR과 업종 비교

- 재료(EPS·BPS)는 네이버 증권 모바일 내부 API `m.stock.naver.com/api/stock/{code}/integration`에서 받는다 (무료, 개인용·저빈도 허용 범위). 반나절(720분)에 한 번만 다시 받는다.
- PER = 우리 DB의 최근 종가 ÷ EPS, PBR = 최근 종가 ÷ BPS로 **직접 계산**한다. EPS가 0 이하(적자)면 PER은 계산하지 않는다.
- "업종 평균"은 네이버가 고른 같은 업종 주요 회사 5~6곳(`industryCompareInfo`)의 **중간값**으로 한다.
  - 업종 전체(반도체는 174곳)를 다 부르는 건 요청이 너무 많아 하지 않았다.
  - 평균 대신 중간값: 이익이 아주 적은 회사 하나가 PER 1,000배가 넘게 나와 평균을 망가뜨린다(예: 주성엔지니어링 1,131배).
  - 적자 회사와 값이 없는 회사는 빼고, 남은 회사가 2곳 미만이면 비교하지 않는다.
- 문구: 업종과 ±15% 안이면 "비슷", 100% 넘게 높으면 "%" 대신 "약 N배". PER이 100배 이상이면 "이익이 아주 적어서 PER이 크게 나와요" 안내를 붙인다.
- 매수·매도 권유가 되지 않게 "싸다/비싸다" 대신 "이익(순자산)에 비해 주가가 낮게/높게 매겨진 편"이라고 쓰고, 낮고 높음의 뜻이 하나가 아니라는 안내를 항상 붙인다. 색도 등락 색(빨강·파랑) 대신 중립 색을 쓴다.
- 화면: 차트 오른쪽 "💰 주가 수준" 카드(계산식, 추정 PER, 비교 회사 표 포함), 관심종목은 간단 버전.
- 이 브랜치는 main에서 땄다. `feature/disclosure`와 함께 main에 합칠 때 `main.py`, `database.py`, `api.ts`, 관심종목·차트 화면에서 두 기능을 모두 남기도록 충돌을 정리해야 한다.
